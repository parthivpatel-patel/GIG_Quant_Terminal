# Saved research signals and offline allocation proposals

`POST /api/v1/workspace/research-signals` accepts `run_ids` (one to eight distinct saved CPU research run hashes), timezone-aware `now`, and optional `lookback` (default 20, 2–200) and `min_ic_observations` (default 5, 2–200, no greater than lookback). All runs must refer to the same admitted dataset, be available by `now`, and have an eligible forecasting or ranking output. HMM regime probabilities and GARCH variances cannot become return signals through this endpoint.

For the latest shared out-of-sample decision clock, each model's adaptation uses only earlier out-of-sample predictions and outcome vintages whose **knowledge time and label end are strictly before that decision**. The last selected `lookback` date-level cross-sectional Spearman correlations form an IC diagnostic. Both cross sections must vary and contain at least two instruments. Two-name IC is necessarily +/-1 and the report explicitly counts such dates; this is not statistical significance or confidence calibration. A negative IC never automatically reverses a model's signal.

The unnormalized adaptive weight is `max(mean_prior_IC, 0) * n / (n + 20)`, provided there are enough observations and the current model fit converged. Positive weights are normalized across models. Current scores are centered cross-sectional ranks divided by their rank range (minimum denominator one), blended with those weights. This is a documented research heuristic, not a return forecast, optimized portfolio, probability of profit, or economically validated ensemble.

The completed report has `signal_id`, source dataset/run/model hashes, `signal_as_of`, selected-label evidence hashes, diagnostics, actual NumPy/Pandas versions, and unapproved score rows. When historical evidence is insufficient, nonpositive, or current ranks cancel, the **completed report remains AVAILABLE** while `scoring_state` is UNKNOWN and `usable_for_portfolio` is false. The report's availability must not be interpreted as eligibility for allocation. Confidence stays UNKNOWN and uncertainty is NOT_CALIBRATED.

`POST /api/v1/workspace/signals-replay` with only `signal_id` verifies the immutable artifact, publication index, original dataset, saved CPU runs/models, and deterministic scoring replay. Files and index live below fixed `research-signals/` paths; request inputs cannot choose paths or URLs. Registration is bounded to 1,000 reports. A detached load cannot mutate cached evidence. The `signals-research` terminal engine exposes this report in Signals, Models, Research, Portfolio and Risk, with explicit UNKNOWN freshness when no policy is supplied and STALE state when the publication age exceeds it. A displayed research report is not the accounting engine's reconciled portfolio.

## Existing allocation and execution path

The existing `research-allocate` endpoint now requires **exactly one** of `run_id`, `signal_id` or `pair_run_id`, retaining its other explicit mark, cash, lot, exposure, freshness and cost inputs. All sources are hash-verified original research artifacts. No generated ensemble is re-registered as a fitted CPU model. Signal scoring must be eligible and pair research must contain eligible current nonzero leg proposals.

CPU and ensemble ranks use the retained quantile constructor. Pair proposals preserve their relative signed hedge weights, reducing all legs by one common factor to fit the requested gross and name caps. They are not ranked as independent stocks. Explicit `n_long`/`n_short` counts must match the aggregated nonzero pair legs. Lot truncation introduces disclosed discrete share differences from the fractional research hedge. Multiple eligible pairs aggregate their signed weights before common scaling; offsetting legs can reduce exposure.

Every plan retains the source kind and original identity, source marks, model hashes, target/prior positions, total traded notional over NAV (`turnover_nav`), modeled commission plus slippage, and existing worst-case asynchronous gross/net/name/sector/factor/cash checks. Optional `max_turnover` (0–8 NAV units) and `max_transaction_cost` (nonnegative USD decimal text) add hard proposal caps. These inputs are validated before accounting mutation. A restrictive policy returns ERROR and prepares no intents. Actual future execution costs, borrow availability, fees and liquidity remain unknown; these bounded cost assumptions do not prove execution feasibility.

The separate `research-prepare` endpoint still creates only idempotent durable **offline intents** after account, clock, kill-switch and retained-order checks. Acknowledgement and fills are separate explicit simulation actions. Position and cash reconciliation uses the existing Decimal FIFO ledger, not the fractional-weight research backtest. No signal, pair fit or saved report approves an order or opens brokerage connectivity.

## Focused evidence

`tests/test_signal_workspace.py` checks an explicit numerical scoring reference, strict correction/label-end knowledge-time exclusion including nanosecond equality boundaries, negative and insufficient IC behavior, real LightGBM ensemble persistence/replay, defensive reads/index tamper, turnover/cost rejection, pair hedge-ratio common scaling, durable offline preparation, explicit partial fills and exact restarted cash/NAV reconciliation. Existing persisted-flow tests continue to exercise the original `run_id` contract. The synthetic fixtures establish implementation behavior only; they are not observed provider coverage or economic validation.
