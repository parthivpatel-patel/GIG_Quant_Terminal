# Bounded container validation after VFS exhaustion

The surviving execution environment uses Docker 28.4.0 with the VFS storage driver. The prior task safely recovered roughly 2.9 GB by deleting one exact stopped task container and four exact task-created, nonshared reclaimable build-cache records. All persistent volumes, verified base images, historical October images/caches, source, dependencies and recovery evidence were preserved. Cleanup metadata is retained under `next-operations-cleanup-*.json` in the checkpoint evidence.

The revised Dockerfile avoids repeated full filesystem snapshots for source and wheels. A read-only BuildKit context mount feeds one build-stage RUN, which installs the compiler and builds package/dependency wheels. The runtime RUN mounts those wheels read-only, installs offline, copies configuration and creates UID/GID 10001. It includes calendar, LightGBM and statsmodels dependencies plus libgomp1 for LightGBM's OpenMP runtime. Torch, Transformers and restricted FinBERT weights are not installed by the default image. The configured proxy and CA secret are retained, with normal TLS verification; neither the CA nor provider credentials are copied into layers.

`scripts/check_container_recovery.py --evidence-dir <new-directory>` performs preflight only. `--build` explicitly freezes allowed source inputs, builds the actual Dockerfile and, if successful, runs native parity and HTTP restart checks. It requires at least 3 GiB free and aborts the build if the free-space reserve falls below 512 MiB or its bounded deadline expires. Runtime creation has a separate storage reserve gate. The script never prunes or changes the daemon/storage driver.

The source context excludes recovery archives, environment files, credential files, host compiled binaries and restricted weights. Runtime checks use the newly built image without source binds, UID 10001, a read-only root, no network or host ports, bounded memory/CPU/PIDs and a retained task-labelled persistent volume. They verify real installed dependency imports, C++ numerical parity, acknowledgement without position creation, explicit partial-fill reconciliation, durable TWAP admission without automatic dispatch/fill, kill persistence and identical GET-only execution/portfolio/risk content after restart.

A preflight is not an image build. An image build without passing runtime checks is not restart acceptance. Actual results are recorded in the command's evidence directory with source manifests and the image ID. x86_64 results do not establish ARM64 runtime support. Earlier ARM64 cross-compilation/QEMU evidence is separate from physical Ubuntu 24.04/Oracle Ampere validation. T4 remains T4_NOT_CERTIFIED.
