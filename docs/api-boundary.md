# API and snapshot boundary

The Phase 7 boundary work is research software, not a trading authorization or
an institutional certification. Evidence for reproduced upstream defects is in
`docs/evidence/baseline-serialization.json`. That file was generated by extracting
the actual baseline functions from local source-snapshot commit
`4ae7e4a2d2db8bb71711f8af88af9b643d4aa259`; it records source rewriting, mutable
cache state, integer rounding, and a synthetic provider diagnostic leak. It
contains no real credentials. The broker override repair has separate execution
tests and is outside this document's serialization evidence.

## Canonical JSON

`gig.service.serialization.dumps`, `loads`, and `normalize` form the common
boundary. JSON is UTF-8, sorted by map key, emitted without insignificant
whitespace, and rejects duplicate decoded map keys. Input strings, including
research source prose containing `NaN`, are preserved without replacement.

The default bounds are 1,048,576 encoded bytes, depth 32, 50,000 visited nodes,
10,000 items per collection, and 65,536 Unicode characters per string. UTF-8 byte
size and string character size are separate limits. Expanded scalar tags obey
wire depth and collection bounds. Numeric NumPy arrays become bounded lists;
object-array and container cycles are rejected. Unsupported objects, bytes,
nonstring map keys, malformed JSON, malformed UTF-8, lone surrogate code points,
and unescaped control characters are rejected with public codes. The encoder
never invokes an unsupported object's `repr`.

Python/NumPy integer values within `[-(2**53-1), 2**53-1]` use JSON numbers.
Larger integers use `{"$integer":"9007199254740993"}`. Decimal values use
`{"$decimal":"1.2300000000000000001"}`, retaining their decimal text, trailing
zeros, sign, and exponent. These tags are wire representations, not instructions
to coerce them back into JavaScript numbers. The reader does not automatically
interpret application objects with reserved-looking keys as scalar objects.
An original JSON integer token remains an exact Python integer on admission;
the encoder introduces its tag when producing a browser-safe response. Python's
integer-to-decimal digit security limit remains enabled; values beyond it fail
with `INTEGER_TOO_LARGE` rather than disabling that protection.

Finite binary64 values, maximum finite magnitude, representable subnormals, and
signed zero round-trip. NaN and either infinity fail. A nonzero JSON token that
underflows binary64 to zero fails with `NUMERIC_UNDERFLOW`. NumPy floating types
wider than binary64 fail explicitly instead of narrowing silently. Ordinary JSON
fractional number tokens retain the declared binary64 contract; exact decimal
input must use an explicit Decimal admission path rather than infer exactness
from a binary64 number. No economic precision is inferred from JSON syntax.

Aware Python datetimes retain microseconds; aware pandas timestamps retain
nanoseconds. Both emit explicit UTC offsets. Naive or missing timestamp objects
fail. Timestamp strings in general research source remain verbatim strings.
Typed provenance uses the shared `aware_timestamp` admission function, which
rejects more than nine fractional digits, naive timestamps, and timestamps
outside the supported nanosecond range before pandas could truncate precision.
Timezone-equivalent provenance timestamps canonicalize to the same instant.

## Contracts and replay

`Contract.admit` and `EnvelopeSchema` both enforce state semantics. AVAILABLE
requires data and no error; STALE requires retained data and its original
timestamp. UNAVAILABLE, UNKNOWN, and ERROR carry null data; ERROR also requires a
classified public error. Data-carrying states require a known classification.
The states do not infer feed freshness, readiness, broker access, or trading
approval from field presence. AVAILABLE describes the requested result, which
may itself be an explicit diagnostics report of unavailable dependencies.

The versioned envelope preserves source, classification, source/instrument/model
identity, model version, as-of precision, evidence state, readiness, and scope.
Its SHA-256 binds the canonical envelope excluding `content_sha256`. Direct
schema validation checks serializability, semantic state, and digest, so a
permissive schema cannot admit data that later fails this wire contract.
`Contract` stores immutable canonical bytes, validates direct construction, and
returns fresh detached objects. Mutation of builder inputs or returned objects
cannot alter admitted bytes. Tampered or noncanonical replay bytes fail.

External errors use only `public_error`'s fixed code/message pairs. Provider
exception text is excluded from both thrown-error responses and successful
fallback payloads. Ollama status omits endpoint userinfo, path, and query details;
its research prompt and returned question preserve the original question text.
Operator-authored research text is not rewritten as a supposed redaction step.

## Legacy research and snapshot cache

Old research artifacts can contain bare nonstandard `NaN`/`Infinity` tokens. Only
the explicitly selected `legacy_nonfinite=True` reader admits those tokens as
null; strict API ingress rejects them. This reader works through JSON token
callbacks, so quoted source prose is untouched. Research results expose the
original file's byte count and SHA-256 plus the legacy-null policy. The source
file remains unchanged. Metric counts remain exact integers through admission
and acquire integer tags at the wire boundary when needed. Invalid field shapes
return a sanitized ERROR rather than escaping the reader.

Research and JSONL history files are bounded before reading more than the
declared byte limit. Malformed history rows are counted explicitly; no valid rows
plus rejected rows is ERROR, not an empty success. Original source text and
configuration strings are preserved, with source-file and parsed-line hashes.

The snapshot cache admits canonical bytes before storing a value. Every read
decodes a detached object; no caller receives the stored object or an alias of
the builder's input. Expiry uses a monotonic clock and the cache is capped at 128
entries. Unsafe values fail before cache insertion. Last-known database
observations after a read failure are explicitly STALE. Neither file size nor a
freshness field elsewhere can invent a bar count or database readiness. Newly
observed counts may decrease. Data freshness and operational readiness remain
UNKNOWN until separately established.

## Verification

Run the focused offline regressions with:

```sh
PYTHONPATH=src python -m unittest discover -s tests -p test_api_boundary.py -v
```

The suite covers numeric extremes, identity, Decimal tags, timestamp precision,
equivalent timezones, malformed input, duplicate keys, bounds, cycles,
unsupported objects, deterministic ordering, immutable admission/cache replay,
research source preservation, state/schema/digest consistency, stale database
truth, and mocked provider diagnostic failures. No provider connection is used.
Broader HTTP, UI, execution, and numerical integration evidence is reported by
the checkpoint runner; this document does not substitute for those checks.
